# Year-End Countdown 2026 — project notes (for Claude and for the owner)

> 给主人的一句话：这份文件是“项目地图”。以后让 Claude（聊天里读 GitHub，或 Claude Code）看这个项目时，它先读这里，就知道**改什么要去哪里改、哪些文件是自动生成的不要碰**。每个项目都放一份。

## What this is
A static website (no build tools, plain HTML/CSS/JS). Mobile-first page for a church group choosing where to stay for the Year-End Countdown 2026 (2 days 1 night, around Kuala Lumpur). Shows places with distance from the church (FGA CYC Kuchai Lama), prices, a map, a compare page, likes, one vote per person, comments, and a share button that gives the REAL place link (Airbnb / official site / Google Maps), not this website.

- Hosted on Vercel, deployed from a GitHub repo (the **deployment repo**, e.g. `year-end-outing`).
- Votes and comments are stored in the owner's Google Sheet through a Google Apps Script web app. People sign in with Google (Google Identity Services). Names of who liked / voted / commented are public; emails stay in the sheet only.
- Page language: English + Chinese toggle (EN / 中). Website copy is English, Chinese text lives in `data/zh.js`.

## Two places — do not mix them up
1. **This source project** — all editing happens here.
2. **The deployment repo** — holds ONLY the built files (about 14): `index.html` (everything bundled into one file), `config.js`, `prices.js`, `user-photos.js`, `assets/user-photos/…`. Never hand-edit `index.html` there. It is produced by `python tools/make_site_folder.py "<path to the deployment repo folder>"` (or double-click `update-site.bat`), then committed and pushed with GitHub Desktop. The tool keeps the deployment repo's own `config.js` unless `--with-config` is given.

> **Current setup (31 Oct 2026):** the owner's GitHub folder IS this project folder (`update-site.bat` has `REPO` = this folder, remote `Jeff-0618/year-end-outing`). Vercel serves `index.html`, `app.js`, `styles.css` and `data/` straight from the repo, so **no bundling is needed**, and `index.html` here must stay the small template that loads `data/properties.js`, `data/zh.js` and `app.js` (restore it with `git show e8eb510^:index.html > index.html` if it ever becomes a 280 KB bundle). `tools/make_site_folder.py` now refuses to build into the project folder itself; before, it overwrote `index.html` with the bundled copy and then crashed with `SameFileError` on `prices.js`. The two-folder description above only applies if a separate deployment folder is used.

## Generated or fragile — do not edit by hand
- `site-to-upload/` — generated by `tools/make_site_folder.py`.
- `user-photos.js` and `assets/user-photos/**` — generated by `tools/add_photos.py` (photos are shrunk to 1280 px, location data removed). `assets/user-photos/dusun_bonda/` holds the owner's own 10 photos that are referenced by name in `data/properties.js`.
- The `"id"` of a place (e.g. `gm_pool_pd`) ties together `data/properties.js`, `data/zh.js`, `prices.js`, `photos-to-add/<id>/`, votes in the sheet. Never rename one.
- Do not run `tools/download_photos.py` (creates 100+ files; the site shows Airbnb/official photos from their own links).
- `tools/removed-places.json` is a backup of places taken off the site (not available / over budget). Do not delete it.

## Data rules
- Do not invent facts. Unknown stays unknown (`?`, `"Not collected yet"`). Amenity status words: `confirmed`, `not_provided`, `not_disclosed`, `additional_charge`, `need_confirmation`.
- Distances are straight-line from the church (area level), not driving time. Coordinates are approximate (town level).
- Airbnb photo `remote` URLs must have NO query string (`https://a0.muscache.com/im/pictures/<id>.jpg`). The app adds `?im_w=720` / `?im_w=1200` itself; a second `?` breaks the image.
- Look (4 Nov 2026): the "v3 look" block at the end of `styles.css` is the visual layer (motion only when the device allows it). The New Year countdown on the places page is `countdownHtml()` and `tickCountdown()` in `app.js`; delete those and the `tickCountdown();` call to remove it.
- GM Pool Villa Port Dickson = TWO DIFFERENT villas booked together (the owner confirmed): Viking (3 rooms, 3 bathrooms, max 15 incl. 4 extra beds) and Mermaid (3 rooms, 4 bathrooms, max 13 — the owner agreed to follow the official site), each with 1 private pool; RM1,480 per villa (super-peak), RM2,960 for both; 28 people in total. Numbers on its page are for both villas together.
- Places currently in `data/properties.js`: airbnb_a, airbnb_b, airbnb_c, dusun_bonda, pd_pool, batu_gajah, bentong_actb, hh_melaka, gm_pool_pd, aoya_villa. Only the ones in `config.js` `shortlist` are shown on the page. When a place is replaced (e.g. `hh_melaka`), give the new one a NEW id: reusing an id would hand the old place's likes to a different place.

## How likes / votes / comments work (so changes do not break them)
- The page never waits for the sheet: a tap is shown at once, saved in the background one request at a time (`Soc.pending`), retried twice, and synced again about a second later. What is shown = `Soc.base` (last known sheet data) + `Soc.pending`.
- Anonymous person id (`uid`) = HMAC of the email, made by the script; the page never sees emails or Google ids.
- Sheet tabs (the script upgrades older sheets by itself — keep that working): `Questions` = Time, Venue, VenueId, Name, Question, Lang, Reply, Email, CommentId, Uid, Edited. `Votes` = Time, VoterId, Type (like/pick), VenueId, Venue, Name, Email, Uid. `Results` is rewritten (at most every 30 s).
- Comments: owner can edit/delete own; admins (`ADMIN_EMAILS`) can delete any, never edit others.
- **Sheet script (synced 1 Nov 2026):** `tools/google-sheet-script.gs` is now an exact copy of the script that is live in Apps Script (it has `edit_comment`, `ADMIN_EMAILS`, `votes`/`cid`/`uid` answers, cached reads, Results refreshed at most every 30 s). The root `google-sheet-script.gs` is an OLD leftover copy — never paste it into Apps Script, it would break likes and comments. After changing `tools/google-sheet-script.gs`, paste it into Apps Script and deploy a New version (step 5 below); otherwise the repo and the live script drift apart again.
- Weak spots found in the live script on 1 Nov 2026, **patched in `tools/google-sheet-script.gs` (4 small changes; the patch only reaches the live site once the owner pastes the file into Apps Script and deploys a New version)**: (1) after a like/vote is written, `touchResults_()` rewrote the Results tab inside the same `try`, so a Results-tab problem made the script answer `ok:false` although the vote was saved (the page showed "could not save", the like reappeared later); it is now wrapped in its own `try/catch` and logged with `console.error`. (2) `lock.waitLock(20000)` was outside the `try`, so a busy sheet answered with a Google error page; it is now inside, so the page gets JSON ("Lock timeout") and retries. (3) `doGet` → `catchUpResults_()` could make the whole page load fail when the Results tab was broken; it is now wrapped too. If a like still fails after deploying, read the reason in the toast or in Apps Script → Executions.
- When saving a like/vote/comment fails, the toast now says why: "Could not save … check your connection" = no connection (retried twice); "The server could not save this … [reason]" = the script answered with an error (the reason is the script's own message; the owner can also see it in Apps Script → Executions). A busy sheet (lock / timeout) is retried twice before the toast.
- If `config.js` has no `sheetUrl` the page works in "this phone only" mode; with `sheetUrl` but no `googleClientId` it asks for a typed name instead of Google sign-in.

## Normal workflow for a change
1. Edit the source files above.
2. Preview: double-click `start.bat`, open http://localhost:8000.
3. Run `update-site.bat` (adds new photos; with a separate deployment folder it also builds and copies into it; with the current setup it only adds photos).
4. GitHub Desktop → write a summary → Commit to main → Push origin. Vercel updates in about 30 seconds.
5. Whenever a `.js`, `.css` or `data/` file changes, bump the `?v=N` number on every script and stylesheet tag in `index.html` (all of them, to the same new number). Otherwise browsers keep the old file, and the page shows old data.
6. If `tools/google-sheet-script.gs` changed: paste it into Apps Script, keep `CLIENT_ID` and `ADMIN_EMAILS`, then Deploy → Manage deployments → pencil → New version → Deploy.
